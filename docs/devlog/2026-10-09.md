## CANDIDATE STATE-MACHINE INCIDENT — Safety / Liveness / Provenance（→ ISSUE-023）

三层不变量框架（本事件按此演进，archive 见 ISSUE-023）：

- **Safety**：作废（obsolete）结果必须永不发布。
- **Liveness**：控制器必须最终离开 Running（不允许无限期 busy）。
- **Provenance**：在途请求必须终身绑定创建它的 configuration
  owner/epoch；provenance 永不 rebase。

事件四步演进：① revision stale guard 保住了 Safety（旧结果被正确丢弃）；
② 该分支纯早期 return 破坏 Liveness——Running 永久化（single-flight 吞掉
同文档重试、delete blocker 常驻、无任何异步机制可终局），定性 P1；③ 首个
liveness 修复（C1）以 rebase `pendingConfigRevision_` 处理 owner swap，
重新打开 Safety——A 期请求可在 B 所有权下通过全部 guard 发布，A→nullptr
时条件性 revision guard 被整体绕过，定性 P0（C1.1 只读审计发现，未提交
开发期，无生产事故）；④ 最终设计（C1.2）把 owner 身份变更视为失效边界。

**已实现方案**：`CandidateExtractionController` 经 `configurationChanged`
连接响应同 owner revision 变更；`setRuntimeConfiguration` 中 owner 身份
变更（A→B / A→nullptr）且 Running ⇒ 共享私有辅助 `invalidateActiveAttempt()`
立即执行（generation=0 令旧完成永不可匹配 + document/content 身份清空 +
state Running→Idle、busy=false）；绝不 rebase；same-pointer = 精确 no-op；
completeAttempt guards 零改动零弱化（stale 回调首先被 generation guard
拒绝，Idle state 为附加独立防御条件——不声称同一回调上双 guard 都执行）。
连接所有权：断旧一连新、same-pointer 防重复、QObject context 析构安全
（审计 PASS）。接受的边界：**NETWORK CANCEL = NOT IMPLEMENTED**——作废
请求可物理完成并消耗配额，其结果不可发布。

**验证证据（定向 ai_settings target）**：C1 REAL RED = set21/staleCred01/
staleCred02（`"running"` vs `"idle"`）×3，staleCred03 保持 GREEN → 修复后
36/36；C1.2 REAL RED = ownerSwap/nullOwner ×2，sameOwner 控制组修复前
