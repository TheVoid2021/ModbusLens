### 4. 本轮最有价值的发现（供 Human review 用）

1. **`README.md` §11 已知限制已过时**（`[C-03]`）：声称「无 register map / 工程单位层」，
   但 M11 已交付 7 种解码类型（含 UInt32/Int32/Float32 + 字序）、M12 已交付设备档案
   register map 与 `scale/offset/unit`（`src/core/profile/DeviceProfile.h` 冻结公式
   `decodedValue * scale + offset`）。**README 自身亦不自洽**（§2 已提到设备档案）。
   仍成立的部分 = 异常码 0x02 的诊断路径不指认具体寄存器语义。
   → **这是自动化面试风险最高的一条**：面试官打开仓库会发现能力比声明更强。
2. **历史数字口径需统一**（`[C-05]`）：`docs/12` §1/§4.1 的「24 个 CTest 目标」是 v1 快照（现状 **70**）；
   `docs/INTERVIEW_NOTES` F10 与 `T028` §2E 的「2 份 ADR」是事实错误（实测 **3** 份，
   `ADR-003` 自 `f649270` 起在库内，早于 T028）。
3. **规划与实现的落差**（`[C-02]`）：`docs/02` D1 把 `IFrameSource` 列为「三模式复用的关键」，
   但 `grep -rn IFrameSource src/ tests/` = **0 命中**，`src/io/` 与 `src/app/` **从未创建**。
   实际成立的共享形式 = 复用同一批**核心函数** + 可执行口径断言（Golden Replay == Simulator Demo）。
4. **同日时序差**（`[C-04]`）：`docs/09` 写「恰为六状态，无第七个」，
   同日 ADR-003 批准并实现第七状态 `ExpectedNoResponse`——两条当时都为真。
5. **项目时间范围**（`[C-01]`）：`docs/11`/`docs/12` 写 2026-09-05→09-14（M8/T015 快照），
   Git 实测 **2026-09-05→2026-10-08**。
6. **`std::filesystem` 是常见误报**：技术栈核验时实测 `src/` 与 `tests/` 命中 **0**——
   持久化由 adapter 层 Qt JSON（`src/ui/profile/ProfileStore.cpp`）承担，故**未列入**技术栈。
