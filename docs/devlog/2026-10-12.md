## 3. `3496794` — T034-G3: harden fake chat server teardown（18:17）

- **2 files / +78**。
- **问题（析构顺序 UB）**：`FakeChatCompletionsServer` 成员按声明逆序销毁——
  `connections_`（声明最后）**先于** `server_`（声明第一）销毁；而 `server_`
  销毁其子 socket 时，socket 的 `destroyed` 信号仍连着触碰 `connections_` 的
  lambda（receiver = `this`，仅基类析构时才死）⇒ 对已析构 `std::vector` 的
  use-after-destruction（UB；依堆复用间歇 SEGV）。
- **修复**：显式析构函数在**全成员存活时**确定性拆除：停止接受 → 丢弃未收养
  连接 → 断开 receiver==this 的全部回调（`destroyed` + `readyRead`）→ 先
  swap 出簿记（空容器仍安全可读）→ 逐个 `delete` socket（非 deleteLater，
  不依赖后续事件循环）。
- 定性：**测试基础设施缺陷**（非产品缺陷）。

## 7. B2.2 轮构建问题三链（10-11–10-12；会话记录）

> 来源：`.workbuddy/memory/2026-10-12.md` 与 `2026-10-13.md`。`modbuslens`
> app target 构建失败被三个独立原因叠加（初判「环境异常」不成立）：

1. **stale qmltypes 产物**（`build/release/ModbusLens/*.qmltypes`）⇒
   qmltyperegistrar 写目标失败退出 1（清理后该步恢复）；
2. **瞬时「拒绝访问」**：qmlcachegen 对**新写出的** `.cpp/.aotstats` 随机
   access denied（每轮失败文件不同、重试即过；串行 `-j1` 也出现 ⇒ 非并发竞态，
   疑似 Defender 实时扫描锁新文件）⇒ **重试循环收敛（≤40 轮；6→4→3→2→1
   递减后全清）**；
3. **真编译错误（被前两者掩盖）**：`main.cpp` 的 `GateQaRunner` 仍实现旧
   `begin` 签名 ⇒ `override` 不匹配；改为新签名后 EXIT=0。

- 结论纪律：app target 构建失败**先跑重试循环**，**收敛到固定 1 步 = 真错误**。
