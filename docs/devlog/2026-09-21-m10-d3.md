## W1. 实现要点

- **新增 `core/active/ProductWriteCapability.h`**：`kProductWrite06Supported` = 结构性产品能力常量
  （encoder + protocol/session + Controller atomic dispatch + evidence 集成四者齐备），
  **不是** runtime availability。
- **新增 Controller 原子操作** `confirmAndDispatchPreparedWrite(token)`：输入仅 opaque token；
  顺序固定 **final guards → consume → encode → start**；编码使用 **consume 前捕获**的不可变快照
  （因为 `PreparedWriteStore::confirm()` 会 `reset()` 清空 snapshot —— 读值不是 chain 中的一步，
  chain 仍是 guards→consume→encode→start）。
- **typed 结果** `PreparedDispatchResult{confirmationAccepted, dispatchAttempted, rejectedReason?,
  startResult?, localError?}`；**复用** `ActiveStartResult` / `TransportDisposition` / `ActiveTransportTerminal`。
- **提取共享 `startActiveDescriptor()`**（从 FC03 路径抽出）并由 FC03 回接 —— 读写共用同一
  in-flight 记账（pending / busy / BusyBecameTrue 失效 / clearSerialError / serialStatusChanged），
  **避免 write-only lifecycle**。
- **`ConfirmRejectReason += CapabilityUnavailable`**（原 6 值确实缺 capability 维度；最小扩展，
  未新建第二套 taxonomy）。
- **fake seam**：`setSubmissionAcceptedBytes(0)` 原本会**穿透到完整接受**；审计确认全仓
  **无任何 `0 = disable override` 依赖** ⇒ 直接定义 0 = zero-accept（attempt +1 / send +0 /
  NotSent / no pending / no terminal / 不进 ADU log）。
- **`write06Supported`**：只读 **CONSTANT** Q_PROPERTY（无 setter、无 NOTIFY）——能力是代码事实，
  没有真实 runtime 变化需要广播。

## W2. 关键实测

```text
R1 full accepted   ：attempt 1 / send 1 / ADU log 1（逐字节 = G3 字面量 11 06 00 01 00 03 9A 9B）/
                     PossiblySent / Consumed / busy；echo 后恰好一条 0x06 Success（同 session）
R2 acceptedCount=0 ：confirmationAccepted=true ∧ dispatchAttempted=true ∧ attempt 1 ∧ send 0 ∧ **NotSent**；
                     no pending / no terminal / zero transaction；可观察 non-success（hasSerialError）
R3 short submission：PossiblySent + **恰一条** ShortSubmission terminal（intended ADU + acceptedCount=3）
R4 guard 矩阵      ：disconnected / busy / stale session / source changed / prepared **0x10 → CapabilityUnavailable**
                     —— 五者 confirmationAccepted=false、attempt=0、send=0
R5 token reuse     ：Consumed 后同 token **连调 10 次**，零额外 attempt / send
Guard ≠ NotSent    ：**专门 oracle** —— guard failure 的 result **没有** startResult（不存在 TransportDisposition）；
                     acceptedCount=0 的 result **有** startResult{NotSent}
Busy 稳定性        ：busy false→true **不**把 Consumed 改写成 Invalidated(BusyBecameTrue)（store 只作用于 Prepared）
集成               ：0x06 的 Success/Exception/CrcError/echo-mismatch ProtocolError/Timeout 全部进入**同一**
                     Active Serial history（无 Write History 第二套）；terminal 仍排除在 rows 与 statistics 外；
                     混合 FC03+FC06 批次 observed=3=pending+completed、successRate=2/3、latency 只取 Success；
                     diagnosis 同一 deterministic batch（含 0x06）实测出现「无响应超时」
```
