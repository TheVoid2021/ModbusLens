# T001.1 — Bootstrap Documentation Cleanup

## Goal

对 T001 建立的工程管理与可移交性做收尾：修复文档命名与措辞问题、提供标准化的本机 preset 模板、把 BACKLOG 拆分为细粒度任务，使项目更容易被"另一台电脑 / 另一个 AI Coding 平台"接管。不实现任何 Modbus 业务代码，不改动 `src/`。

## Background

- T001 交付后遗留两类问题：(1) 演示指南文件名为笔误 `05_DEMO_GUIDIDE.md`；(2) `QTFRAMEWORK_BYPASS_LICENSE_CHECK=1` 在多个文档中被表述得像"项目必要依赖/官方推荐方案"，而它实际只是本机 Qt 安装在 AutoMoc 时出现 qtlicd 警告的临时规避手段。
- 可移交性缺口：本机工具链路径只存在于 gitignore 的 `CMakeUserPresets.json`，没有一个"新人/新平台照抄"的模板；ENVIRONMENT 也没有给出"换电脑怎么重建环境"的明确流程。
- BACKLOG 原任务粒度过粗（T002 一个任务同时含 CRC、帧编解码、查表优化、基准、fuzz），不符合"每次只做一个小任务、每任务可独立验证"的规约。

## Problems Encountered

1. 文件名笔误 `GUIDIDE` 已在 6 处文档被引用，手工改有遗漏风险。
2. 本机 preset 与模板的验证存在鸡生蛋问题：模板路径是占位/示例值，无法直接在本机跑通。
3. `QTFRAMEWORK_BYPASS_LICENSE_CHECK` 的历史表述（"官方给出的开关"）可能被后人当作项目依赖复制到新环境。
4. 单一 commit 内无法自引用自己的哈希，且本任务要求"提交一个独立 Git commit"。

## Solutions

1. 用 `git mv` 保证历史；`grep -rn "GUIDIDE"` 全量定位，逐一修正后复检，仅保留 T001 史档案中带批注的历史记录。
2. 用"模板结构 + 本机真实路径替换"的等价文件临时替换 `CMakeUserPresets.json`，完整跑 configure/build/test（含 clean 全量重建触发 AutoMoc），证明模板结构本身可用；完毕后恢复原 preset。
3. 统一改写为"临时环境处理手段、非项目依赖"；example 模板不含该变量；ENVIRONMENT FAQ 单独解释何时需要；T001 档案用追加批注修正口径。
4. 依 PROJECT_STATUS 既有约定：docs-only 提交不推进 LKGC（LKGC 仍为 `aa337f6`），本任务提交哈希以 `git log`/本文件的提交信息为准，并在对话总结中报告实际哈希。

## Knowledge Learned

- 文档重命名的正确姿势：`git mv` + 引用扫描 + 历史档案批注三件套，比"改名+手动改引用"更可追溯。
- 机器相关配置的通用模式：**提交模板（example，与具体机器无关）+ 机器私有实例（gitignore）**，并用"临时等价替换验证模板"消除"模板没法在本机跑"的验证盲区。
- LICENSE 类环境变量的准确性纪律：如实说明来源（构建输出提示）与范围（本机临时），不上升成"官方推荐/项目必要"。
- 任务拆分原则：每个任务 = 一个可独立验证的垂直切片 + 一个可写的面试知识点；"不含清单"与"包含清单"同等重要。
- 单提交自引用哈希不可实现；以"LKGC + 约定 + git log"组合解决，把约定写成制度而不是临场发挥。

## Potential Interview Questions

1. **为什么 CMakePresets 要分两个文件？各自装什么？哪个进仓库？** —— 通用性 vs 机器差异隔离；`CMakeUserPresets.json` 被 .gitignore 精确忽略是第二道保险。
2. **如何保证项目代码不依赖任何机器的绝对路径？** —— 约定红线 + `git grep` 自检命令 + example 模板用示例值；被忽略文件即使 `git add -A` 也不会误提交。
3. **为什么 example 模板里不放 `QTFRAMEWORK_BYPASS_LICENSE_CHECK`？** —— 它是本机 qtlicd 警告的临时处理，非项目依赖；放进模板会让所有机器无谓继承，成为隐性环境假设。
4. **把 CRC、帧模型、0x03 编解码拆成三个任务的意义？** —— 任务粒度 = 验证粒度；每个任务单独可测、单独可答（面试知识点），避免一个"大任务"半成品状态。
5. **docs-only 提交为什么不推进 LKGC？** —— LKGC 语义是"构建+测试双通过的提交"；文档提交不改变构建事实；推进它反而误导协作者认为有代码变化。
6. **如何验证一个"别人照着做的模板"真的能 work？** —— 用模板结构等价替换本机配置完整跑三连 + clean 重建触发 AutoMoc，验证后恢复原配置。
